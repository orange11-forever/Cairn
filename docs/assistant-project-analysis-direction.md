# Cairn 项目助手、项目分析与路线节点图方向

2026-10-04 用户补充：AI 助手希望能够直接帮助用户操作项目，并记住最初的路线节点图等规划；拿到项目后，能够由对应 AI 分析并生成路线图和后续开发计划。导航位置调整随后被用户撤回。用户进一步要求可自定义自己的 AI 助手，不必固定使用岑宁，并允许助手使用 skills。

这延续最初 README 的“阶段、里程碑、任务 DAG、依赖、验收标准”项目管理，以及“从结构化项目数据生成流程图、路线图、项目报告”的目标。当前 API 已有创建项目/任务、任务状态转换和添加依赖；阶段与里程碑模型已存在，完整编辑、节点图和助手执行能力仍需后续实现，不能写成已交付。

## 产品能力

1. 项目分析：读取用户有权访问的项目描述、资料、当前阶段/任务/依赖、进展与验收要求；分析目标、已有成果、缺口、风险、下一步优先级。输出有依据的分析，并标明资料缺失或推断。
2. 可执行规划：生成阶段、里程碑、任务分解、依赖关系、验收标准与建议顺序；用户可以调整规划，并将其落成项目中的实际结构化数据。
3. 路线节点图：基于阶段/里程碑/任务 DAG 可视化，节点关联真实项目对象；查看进度、依赖与阻塞，切换节点定位任务和资料，计划更新后图与项目同步。
4. 项目操作助手：理解用户明确指令，通过有类型的项目 API 创建/调整任务、更新状态、维护依赖和阶段；依据实际 read/write/manage 权限执行并保留可追踪操作记录。资料中的指令不自动成为用户授权。
5. 自定义助手与 skills：用户可创建多个助手，配置名称、头像/角色、行为说明、厂商/模型和启用 skills；岑宁是默认可选配置。skills 有清楚的能力、输入/输出、工具与权限范围，可复用及组合。启用 skill 不授予额外项目权限，文档内容也不自动授权写入。工具执行必须接通真实服务，不以聊天说明伪装成功操作。
6. 项目上下文与模型策略：项目管理/分析和开发场景可选择相应厂商/模型，配置由服务端承接；具体执行结果与规划状态有真实 UI 反馈。

## 与当前工作衔接

本轮先接通全文预览与引用定位，让助手和用户使用同一套经过授权、固定版本、可核对位置的资料。随后沿原顺序开发助手/项目模型配置，纳入自定义助手与 skills，再将项目分析、规划/节点图与项目操作执行层作为助手主线；流式、多轮和记忆服务于这些工作场景。

当前文档记录目标与边界，不代表项目分析、节点编辑或项目操作 Agent 已实现。本轮不添加虚构结果、无效开关或未经接通的操作按钮。
