# Cairn 全文预览与引用定位设计

## 用户目标与范围

用户按既定顺序要求先完成全文预览与引用定位。本轮先支持 Markdown、TXT 和飞书同步后的文本快照，使“选择资料 → 阅读完整正文 → 点击搜索/回答引用 → 定位并突出对应正文”可通过真实 API 完成。

后续补充要求：AI 助手应能操作项目，进行项目分析，生成阶段、里程碑、任务依赖节点路线图与后续开发规划。自定义助手（岑宁作为默认可选角色）与 skills 扩展亦属后续助手需求。这些项目助手需求完整记录于 `docs/assistant-project-analysis-direction.md`。用户已撤回导航位置调整；本轮不新增项目分析/工具执行后端。

保留刚验收的 IDE 布局、主题、山峰/助手资产、多标签、项目切换及来源独立页。全文阅读是普通资料的主内容，资料详情以工具栏入口展开；未支持的二进制文件保留真实资料信息、下载及经过授权的引用上下文。

## 读取 API

新增 `GET /api/v1/projects/{project_id}/knowledge/resources/{resource_id}/content`。查询参数可选 `version_id` 和 `chunk_id`；指定 `chunk_id` 时须同时指定 `version_id`。普通文件打开读取当前已发布 ready 版本；引用打开精确固定其资源、版本和片段。

返回完整字段：

```ts
type KnowledgeContent = {
  resourceId: string;
  resourceVersionId: string;
  title: string;
  mediaType: string;
  format: "markdown" | "text";
  content: string;
  lineCount: number;
  highlight: null | {
    chunkId: string;
    lineStart: number;
    lineEnd: number;
    text: string;
    matchType: "exact" | "range";
  };
};
```

首版仅直接读取可信记录声明的 `text/markdown`、`text/plain`；不依据任意客户端路径或扩展名选择对象。最大原始读取 1 MiB，最多 20,000 行，超限明确失败，不把截断正文称为全文。UTF-8 strict 解码，支持 BOM；归一化 CRLF/CR、去除不可显示控制字符须与既有 Worker `normalize_parser_text` 规则一致，保持引用行号语义。

采用分块有界读取并验证实际字节数与记录 SHA256；错误不得泄漏 object key、存储 URL、内部路径或正文。对象流无论成功/失败都关闭。

## 权限、版本与事务

- 读取前：已有认证身份、当前组织、项目 read、当前成员/角色、来源状态/显式共享策略、资源未删除、当前可读 ready 版本全部核验。引用片段须属于相同资源和该版本。
- 用不可变原始字段记录观察结果，结束数据库事务后再读取对象，不跨存储 I/O 持有数据库事务或锁。
- 读取后在新事务中重新核对当前角色/成员、ACL、来源、资源和版本。SQLAlchemy `expire_on_commit=False` 不能使旧 ORM 实体绕过复核。撤销、停用、删除、换版时丢弃已读内容。
- 本轮不扩展外部飞书权限，不连接或改写历史真实验收数据库。历史上游撤权/删除缺口依旧是独立验收项。

## 公共契约

成功 200，精确 schema 与字段别名。错误使用既有完整 ErrorBody 与 X-Request-ID/traceId 关联：认证失败401；不可见/未就绪/错误片段404；请求参数无效422；已固定版本与当前版本不一致409 `knowledge_changed`；超限413 `preview_too_large`；格式/编码不支持415；对象缺失/存储不可用或内容完整性失败安全503；未知异常安全500。

成功与所有失败保留 `private, no-store`、CORS、nosniff、既有安全/协议头。GET 不引入 CSRF 写操作或 Cookie 变更。OpenAPI 明确成功、全部错误、查询参数关系；生成 SDK/运行时校验同步更新。测试在真实 HTTP 边界逐项断言状态、schema、trace、安全/协议头，以及 OPTIONS/不允许的方法等消费者可观察语义。

## 引用定位

定位信息只来自重新授权的当前版本 chunk，不接受客户端任意行范围作为可信引用。行号须与归一化完整文本对齐。

既有索引有些 chunk 共用较宽的原段落行范围。服务在可信行窗口内用该 chunk 的原文缩窄到唯一匹配的行范围；唯一匹配返回 `exact`。无法唯一匹配时返回可信原区块范围与 `range`，前端明确呈现引用片段及“引用所在区块”，不猜测一个看似精确的错误位置。空、越界、非法定位须安全失败或明确恢复，不使用其他版本补齐。

Markdown 的标题、段落、列表、代码围栏、表格等保留行位置映射。TXT 保留换行与正文。引用激活后阅读区域滚动到对应位置并突出显示，有“回到引用”动作；普通文件浏览不主动跳动。代码复制仍可用，复制错误明确反馈。

## 前端读取与状态

生成 SDK 的 API wrapper 严格校验 200、响应 schema、请求资源/版本/片段一致性，以及 lineCount/highlight 范围。只有当前活动文档挂载正文读取；非活动标签保留标识和标题，不保存正文/摘录。

正文不进入 localStorage/sessionStorage/IndexedDB，不写日志。查询无自动重试/重连读取，离线时立即隐藏正文并取消请求，恢复须显式重新读取。切标签、项目、会话、删除、源停用、401/404/409 或迟到响应时，沿用已验证的取消与隐匿规则，正文新 query key 纳入清理和失效边界。

普通资源可以显示当前已发布正文，元信息若最新版本仍在处理则准确显示版本状态，不伪称已经读到新版本。手动刷新重新授权。原来的资料状态、重试、删除确认、下载与源码引用上下文入口保留；不支持全文的格式使用这些真实能力。

内容按不可信数据处理：禁止执行 raw HTML、危险 URL、脚本、嵌入页面以及文档驱动的远程媒体请求。若采用成熟 Markdown 解析器，渲染仍使用安全 React 节点、禁用 raw HTML/远程图片，并利用 AST source positions 做定位；不得用正则手写一个声称支持完整 Markdown 的解析器。纯文本直接安全显示。

## 验收

真实隔离 PostgreSQL/MinIO/API/Worker，实际上传并索引 Markdown/TXT，测试正文完整性、EOF 内容、CRLF/BOM/控制符、多字节、空白、代码、重复引用、版本变化与权限变化；飞书快照路径验证使用合成上游，不冒充新的真实租户撤权验收。

浏览器覆盖文件点击全文、搜索/回答引用定位、高亮与返回、资料详情/下载、未支持格式、加载/失败/超限、离线、切页/项目/会话/删除、长文本以及桌面/768/360 深浅主题和44px。现有导航保持既有验收范围。

保持最小 TDD 消费者测试，不写源码字符串镜像测试。规格先审查并解决发现，质量独立审查；最终 `pnpm verify` 必须是当前候选的完整新结果。每个新 HTTP 入口覆盖成功、验证、认证授权、基础设施与未预期异常五类路径。
