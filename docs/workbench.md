# Cairn 项目知识工作台

工作台位于 `/projects/:projectId/knowledge`。顶部项目选择器按需读取当前组织可访问的项目，支持分页和手动恢复；选择项目进入它的知识工作台。项目任务、资料、搜索和来源页面共用活动栏与账号外壳。

资料栏连接真实资源列表、分页和上传批次。选择资料在中央打开文件标签；搜索命中或回答来源打开引用标签。标签只保存资源或引用标识和标题；只有当前资料或引用挂载读取控制器，切换、关闭时取消旧请求并移除旧详情或引用缓存，重新打开会重新授权。搜索标签离开后销毁局部搜索状态，返回时可重新提交搜索；不会自动重新执行搜索。项目切换和会话变化丢弃旧标签与内容。

Markdown、TXT 与飞书已发布文本快照以完整正文为主内容。真实全文 API 每次核验当前用户仍启用、资源、ready 版本和权限，并在有界对象读取后重新核验用户启用状态、来源、成员角色和 ACL；资料详情、处理状态、重试、删除和下载仍由工具栏打开。Markdown 保留标题、列表、围栏代码和表格，禁用 raw HTML 与远程媒体，链接只允许 HTTP(S)、邮件及页内锚点；代码可以复制，失败时提示手动复制。未支持的二进制格式保留真实信息、下载和经过授权的相邻引用上下文。

搜索或回答引用固定资源、版本和片段。正文使用可信源行号突出位置并提供“回到引用”。长列表与表格定位到具体引用条目或行；保留父集合源位置，但不把整个集合染为引用，只滚动当前阅读区。索引片段能在可信区块中唯一匹配时显示“引用原文”；重复或无法精确匹配时显示“引用所在区块”和原片段，不猜测位置。普通打开不主动滚动。只有活动标签保留正文查询，关闭、切换、删除、项目/会话变化都取消并清除正文缓存；离线立即隐藏正文，恢复后须明确点击“重新读取正文”，不自动重连读取。不写入浏览器持久化存储。

首版仅支持可信版本记录中的 `text/markdown` 和 `text/plain`，严格 UTF-8（含 BOM），按索引规则归一化换行和控制字符。最多读取原始 1 MiB、20,000 行；超限明确提示下载原文件，不显示截断的“全文”。完整成功显示真实 EOF 状态。版本改变或授权失效会丢弃已读正文。

岑宁面板支持项目私有的持久化多轮问答。桌面左侧“项目对话”与窄屏面板的“选择对话”共享真实分页列表，“新建对话”提供新的草稿；第一次发送才创建会话并提交完整轮次。URL 的 conversation UUID 支持刷新恢复，问题与每轮引用保持对应。输入区固定在面板底部并显示实际项目名称。未配置模型时说明“模型尚未配置”，历史仍可读取；历史引用失效显示回答暂不可用，上下文截断有明确提示。Responses 模型逐段显示经过引用与访问检查的临时回答，完成后才保存；其他协议显示完整回答。

发送不自动重试或离线回放；409、网络失败、契约错误或“停止等待”保留草稿与请求 UUID，必须“重新读取会话”确认结果。已保存轮次恢复后，只有未再次编辑的对应草稿会清空；读取失败保持恢复状态并禁止随机新 UUID 重发。流式请求断开会触发服务端协作取消，但阻塞的上游读取仍需等待返回或超时，已保存结果可重新读取。切换资料、阅读、来源页面保留草稿和所选会话；会话切换取消请求并清理旧回答缓存，项目、组织、用户或登录代际改变清理全部该范围聊天状态。聊天不写入浏览器持久化存储。模型状态表示已配置，不代表外部服务已经连通。

“助手与技能”中的“回答模型”列出服务端允许的模型，保存后作用于当前用户在该项目的下一轮回答，刷新后保留。选择“服务端默认”时使用当前默认模型；显式选择的模型被移除后会提示不可用并阻止发送，须重新选择并保存。每轮历史保留实际使用的模型名称、ID和协议；切换模型不改写旧回答，升级前的轮次不补造模型记录。模型清单由服务端 `ANSWER_MODELS` 配置，端点与密钥不发送到浏览器；部署步骤见 [API说明](../apps/api/README.md)。

飞书功能拥有独立的“来源与同步”页面 `/projects/:projectId/knowledge/sources`。组织管理员可登记来源、显式共享到项目、维护同步间隔、停用与恢复、查看分页同步历史并手动同步。同步完成与索引可检索状态保持区分；普通成员仍看到真实权限说明。飞书身份绑定留在账号登录方式页面。

桌面可收起并恢复资料栏和助手。900px 以下使用资料、内容和助手分区，移动布局不会覆盖桌面偏好。两套主题使用相同结构与交互；控件有键盘焦点，标签支持左右方向键及 Home/End。全屏区域分别滚动，来源页长历史保留可达的末行和分页按钮。

全文接口与生成 SDK 的契约见[全文预览设计](2026-10-04-document-preview-design.md)。本轮不扩展外部飞书授权；真实飞书上游撤权或删除尚未完成的历史验收保持独立。项目分析、路线节点、开发规划与项目操作的后续方向见[项目助手需求](assistant-project-analysis-direction.md)。导航位置保持既有布局。

“助手与技能”可编辑当前项目的个人助手名称与行为说明，勾选只读技能并明确保存。导入区支持 SKILL.md、ZIP 和公开 GitHub 链接，先预览名称/正文/依赖限制，再确认导入；未知结果使用相同请求 ID 重新确认。导入不自动启用，需勾选保存，再从“使用技能”选择；默认问题只填充空草稿，不自动发送。历史显示保存时的助手与技能事实，配置冲突通过重新读取助手与会话恢复。

每个用户在每个项目中可保存最多20个助手。“当前助手”切换当前配置，“新建助手”创建并选用一套空白配置，随后可分别编辑名称、行为、模型和启用技能。已导入技能目录仍由该用户在项目内共享，各助手的启用列表相互独立。原助手在升级和首次新建后继续保留。切换影响当前会话的后续轮次，保留问题草稿和原有对话上下文，历史仍显示当时的助手与模型。未保存配置需先保存或取消才能切换；其他窗口切换后，原配置草稿不会改绑到新的助手。创建/切换结果未知时，须先重新读取助手与技能，不自动重发创建请求。
