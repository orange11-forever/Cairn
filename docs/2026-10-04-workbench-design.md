# Cairn 前端工作台完善设计

## 目标与范围

用户要求依据参考图、当前实现差异及后续功能，设计并实现新的前端；随后要求飞书功能有独立页面，并于本轮明确收窄为“先把前端页面优化完善”。这一最新要求替代早期草案的全文读取 API 扩展。本轮仅修改前端、前端测试及相关界面文档，后端、数据库和生成 SDK 契约保持现状。

参考图为根工作区 `output/imagegen/cairn-ide-workbench-concept-20260928.png`。目标是工程项目成员在连续工作区中浏览资料、搜索、核对引用、询问项目知识和管理飞书来源。现有功能必须真实可用，视觉向参考图靠拢。

## 确定的设计

- 紧凑的 IDE 外壳：顶部品牌和项目切换，窄活动栏，左侧资料列表，中央内容标签与阅读区，右侧助手，底部状态栏。
- 石墨灰深色、蓝色选中态、细边界、平直面板、清晰中文字体；完整浅色主题。保留山峰标志和助手资产，使用现有图标体系。
- 桌面顶部约52–56px，活动栏64–72px，文件栏224–264px，助手340–420px，中间使用剩余宽度。1280/1440/参考图宽度均协调，主要面板独立滚动，输入区固定在助手底部。
- 900px附近转为分区导航；360/390和768视口不横向溢出。控件触达区域至少44px；完整焦点、键盘、加载、空、失败、离线和长文本状态。
- 拆出聚焦的组件及工作台样式，避免在现有大CSS文件尾部持续叠加相互覆盖规则。

## 页面与交互

### 外壳和项目切换

使用真实项目列表和既有路由，支持项目分页、加载、失败恢复。选择项目后进入其知识工作台，并取消旧项目请求、清除旧内容。面板收起/恢复按钮可用且始终保留恢复入口；窄屏分区操作与桌面偏好不会互相锁死。来源页仍有返回资料入口，项目任务页继续正常使用统一外壳。

### 资料与中央内容

左侧列表呈现文件图标、标题和真实处理状态，飞书资料显示来源标记。上传入口保留现有收起/展开、取消、失败和批次跟踪行为。资料详情保持可发现，避免将一组管理表单常驻挤占文件列表。

中央支持文件标签和搜索标签；标签仅在当前会话内保存必要元数据，正文和引用不写浏览器持久化存储。切换/关闭标签取消并销毁旧活动内容，请求迟到不影响新内容。详情、下载、重试和删除仍走现有真实组件/接口。删除清理同资源标签与引用，401清会话，404重新核实当前项目/资源权限，409提供明确恢复路径。

文件详情使用文档式标题、面包屑、工具栏和简洁的信息布局。已有引用接口只能提供命中片段及相邻上下文，阅读界面明确标为“引用上下文”，按locator显示章节/页码/行号并突出命中段落。允许安全地改善段落、标题、代码展示和复制，但不能把三段引用伪称全文，也不能添加演示正文到产品。普通资料没有全文接口时真实显示资料详情和授权下载。

搜索使用独立标签/活动栏入口，结果点击把对应引用打开在中央，保持当前项目、资源版本和原有授权契约。文件标题很长时合理省略，完整标题仍可被辅助技术或详情读取。

### 项目问答

右侧助手以头像、当前问题、回答和来源卡片组织内容。输入框始终可见，含真实当前项目上下文以及发送/取消/清空本轮的操作。保留现有单轮语义、3–500字符规范化、证据不足、限流、网络失败、取消、401、离线、切项目和来源失效处理。消息/代码格式化不得执行HTML、危险URL或自动加载远程媒体；复制失败反馈清楚。不能显示不存在的历史对话或暗示已启用多轮记忆。

### 来源与同步

使用独立现有路由 `/projects/:projectId/knowledge/sources`，在资料栏提供“来源与同步”入口。页面统一外壳、标题/返回导航和表格/列表层次，承接现有飞书来源登记、显式项目共享、状态、同步历史、失败重试、停用/恢复和分页。只读成员与管理员按既有权限区分；保留快照同步完成与索引ready的区别。

飞书登录和身份绑定属于账号设置，不并入文档来源操作。历史真实飞书上游撤权/删除仍未通过，本次UI改动不改变该事实或外部授权scope。

## 后续功能的位置

模型厂商/模型选择将接在助手输入区的上下文工具栏；会话历史和新会话位于助手标题区域；消息容器支持后续流式和多轮；长期记忆的范围与开关进入对应账号/项目设置。当前实现只提供这些组件边界和合理空间，不新增虚构选项、无效开关、假模型状态或后台功能。完整正文预览、新模型配置服务、流式、多轮和长期记忆留后续。

## 验收与保全

使用合成数据在真实浏览器检查参考图尺寸、1440/1280、768、360/390，深浅主题；核对文件/搜索标签、资料与引用、代码复制、项目切换、面板显隐、来源操作、键盘、长文本与输入区可见性。截图须来自实际界面。最多先做一轮集中检查、一次集中修正后确认；独立审查发现的问题另行修正。

新增行为用消费者可见测试覆盖成功、验证、认证授权、基础设施、未预期异常；API无改动，但前端仍验证既有状态/schema/trace/安全协议语义的使用。规格审查先通过，独立质量审查随后通过，最终新的 `pnpm verify` 必须成功。已有注册/登录、资料生命周期、来源管理继续回归。

新工作树 `.worktrees/feat-cairn-workbench-20261004` 精确继承昨天63个候选文件；其余工作树保留。本轮前端改动不覆盖昨天后端/注册成果；不连接或重置历史验收数据库，不读取真实凭据到Web，不提交、合并、推送或发布。
