## 数据库（按性价比排序）

### 1. SQL 查询本身 ★最基础

- `SELECT` / `WHERE` / `ORDER BY` / `LIMIT`
- **`JOIN`**：搞清 `INNER JOIN` 和 `LEFT JOIN` 的区别，以及各自该在什么场合用
- `GROUP BY` + 聚合函数（`COUNT` / `SUM` / `AVG`）
- 子查询

这一层没有捷径。它决定了后面所有东西——ORM 生成的 SQL 你要能看懂，
不然出问题时完全无法排查。

### 2. 索引 ★收益最高

- **复合索引的列顺序为什么重要**（直接对应我们定的"`org_id` 进复合索引第一列"）
- 什么查询用不上索引（典型：在列上套函数、`LIKE '%xxx'` 前置通配）
- `EXPLAIN` / `EXPLAIN ANALYZE` 怎么读

企业级项目的性能问题九成是索引问题。这块靠自学收益极高——它是纯知识，
不需要项目上下文就能学明白。

### 3. 事务与隔离级别

- ACID 各自的含义
- `BEGIN` / `COMMIT` / `ROLLBACK`
- 四种隔离级别，以及各自允许什么异常（脏读 / 不可重复读 / 幻读）

**用户的多线程背景在这里能用上**：事务隔离和内存可见性/竞态是同一类问题，
只是发生在数据库里。

但有个反直觉点要注意：数据库的默认隔离级别通常比想象的松，
**PostgreSQL 默认是 `READ COMMITTED`**，不是可串行化。

### 4. 约束

- 主键、外键（含 `ON DELETE` 的几种行为）
- `UNIQUE`，尤其**多列组合唯一**——这是我们保证摄取幂等的机制
- `NOT NULL`、`CHECK`

一条值得记住的判断：**能用约束表达的规则就别写进应用代码。**
约束是数据库替你保证的，应用代码是靠人记得的。

### 5. pgvector（可放最后，或留到 Day 22）

- 向量列类型、维度
- `<=>`（余弦距离）等距离运算符
- HNSW 索引

有 RAG 背景会很快。

### 不要花时间的

存储过程、触发器、分区表、主从复制、NoSQL 对比。项目里一个都用不到。

## React

失分位置来自 Day 9 的六道问答，很集中，指向两个薄弱点。

### 1. state 的机制和代价（Day 9 问答第 1、4 题都栽在这）

- 为什么受控组件必须 `value` + `onChange` 成对——
  **React 会主动撤销不符合 state 的 DOM 值**（不是被动覆盖，这个区别重要）
- `setState` 不是立即生效的，它触发的是一次新渲染
- 每次 setState 的代价是一次重渲染，所以**不影响渲染输出的值不该进 state**

### 2. 渲染时机 / 什么时候不该用 Effect（第 3、6 题）

react.dev 上两章直接对着这两个弱项，值得逐句读：

- **You Might Not Need an Effect** —— 第 3 题那三个问题的完整版
- **Synchronizing with Effects** —— 讲清 Effect 到底在哪个时刻执行

**读 react.dev 官方文档，不要搜中文博客。** 中文 React 教程里有大量 class 组件
时代的内容，那些模式现在是错的（甚至是反模式）。

### 不要花时间的

class 组件、生命周期方法（`componentDidMount` 那一套）、Redux、HOC、
`React.FC` 类型写法。项目里一个都不用，有些已经是过时的反模式。
