# Tracebase 功能清单

2026-07-30 制定。定位与阶段划分见 [`product-vision.md`](product-vision.md)，本文只列**功能**。

阶段标记：**A** Web 地基（现在）｜**B** 后端数据｜**C** RAG｜**D** 部署｜
**E** 代码感知｜**F** 智能体治理｜**G** 多端｜**H** 企业搜索

---

## 一、搜索与问答（产品的核心动作）

| 功能 | 说明 | 阶段 |
|---|---|---|
| 自然语言提问 | 不是关键词搜索，是问句 | C |
| **每个答案带可点击引用** | 点进去看到原文的那一段，不是文档首页 | C |
| **无证据时拒答** | 明确说"知识库里没有依据"，不编 | C |
| 流式逐字输出 | 长答案不用等全部生成完 | C |
| 停止生成 / 重新生成 | 停止会真的终止后端生成，不只是前端不显示 | A（前端已做）/ C |
| 多轮追问 | 带上下文，"那第二种情况呢" | C |
| 引用悬停预览 | 不跳走就能看到被引用的片段 | C |
| 按来源类型过滤 | 只搜代码 / 只搜文档 / 只搜 PR 讨论 | E |
| 按元数据过滤 | 时间范围、作者、仓库、项目、部门 | C / H |
| 对话历史 | 可回看、可继续、可分享给同事（**分享受权限约束**） | C |
| 答案反馈 | 「有用 / 引用不对」，用于改进排序 | H |
| 保存搜索与订阅 | 这个话题有新内容时通知我 | H |

**为什么"拒答"是功能而不是缺陷**：企业场景里一个编造的答案比没有答案代价大得多。
用户会拿它去做决定。

## 二、资料管理（让知识可被检索）

| 功能 | 说明 | 阶段 |
|---|---|---|
| 上传 | 拖拽、多选、进度显示、**断点续传** | A（校验已做）/ B |
| 格式支持 | 起步 PDF / Markdown / TXT / DOCX；后续 PPT、表格、图片 OCR | C |
| **处理状态可见** | pending → running → succeeded → failed | C |
| 失败可诊断可重试 | 看到失败原因（不是"处理失败"四个字），点一下重试 | C |
| 幂等 | 同一文件传两次不产生重复 chunk | C |
| 文档列表 | 按状态筛选、排序、搜索 | A（已做）|
| 文档详情 | 预览、被引用次数、chunk 分布 | C |
| 软删除 + 回收站 | 误删能恢复 | B |
| 彻底清除 | 合规要求的删除权，内容抹除但留痕 | B |
| 版本更新 | 同一文档更新后，旧引用如何指向 | C |

## 三、代码感知（★ 差异化，阶段 E）

这一组是这个产品和通用企业搜索的区别所在。

| 功能 | 说明 |
|---|---|
| **「这段代码为什么是这样」** | 选中一段代码提问，答案串联 commit message + 当初那个 PR 的讨论 + 设计文档 + 事故复盘 |
| 符号级代码搜索 | 找定义、找所有引用。不是文本匹配——认识 `getUserById` 这个符号 |
| **影响面分析** | 改这个函数会影响哪些调用方、哪些测试、哪些下游模块 |
| **推导式架构图** | 从真实 import / 调用关系生成，**每个节点可点开看文件，每条边可追到那一行** |
| 变更热点 | 哪些文件最近改得频繁，并总结为什么 |
| 新人上手路径 | 给一个仓库，生成"按这个顺序读这几个文件" |
| PR 辅助 | 这个 PR 的影响面 + 相关的历史讨论（"三个月前有人改过同一处，原因是…"） |
| 代码 ↔ 文档双向链接 | 这份设计文档对应哪些代码；这段代码有哪份设计文档 |

**图必须从真实结构推导，不能让 LLM 画。** LLM 画的架构图会自信地错，
而图比文字更容易让人相信。LLM 只负责给分组起人话名字、总结热点原因。

**影响面分析可以在 CI 里跑**（通过 CLI），把结果输出到 PR 评论——
这是让工具进入日常工作流而不需要用户主动打开它的方式。

## 四、智能体（阶段 F）

| 功能 | 说明 |
|---|---|
| 智能体注册 | 名字、系统提示、可用工具、**可访问的数据范围** |
| **权限继承** | 智能体以调用者身份运行，读不到那个人读不到的东西 |
| 工具集 | 检索、代码分析、读文档、调外部 API（受白名单约束） |
| 触发方式 | 手动 / 定时 / 事件驱动（新 PR、新事故） |
| **运行审计** | 每次执行：输入输出、读了哪些资源、调了哪些工具、花了多少 token |
| **成本预算与硬上限** | 按组织 / 部门 / 智能体设额度，超了拦住而不是产生账单 |
| 审批流 | 某些操作需要人确认才执行 |
| 模板库 | 常用智能体：PR 审查、事故复盘起草、周报汇总、值班交接 |
| **提示注入防线** | 文档里埋的"忽略之前的指令"不会被当成指令执行 |

**权限继承是这一组的地基。** 没有它，智能体就是一个越权通道——
实习生的智能体读到 CEO 的文档。检索时用的 principal 集合取自
`on_behalf_of` 那个人，不是智能体自己的。

| 彻底删除请求 | 个保法 / GDPR 的删除权 |

## 六、集成（阶段 H，机器人在 G）

| 功能 | 说明 |
|---|---|
| 连接器 | GitHub、Jira、飞书、Slack、Confluence、Google Drive |
| 增量同步 | 靠 `source_updated_at` 游标，不是每次全量 |
| **删除传播** | 源头删了，索引里必须也删——否则会答出已经不存在的内容 |
| IM 机器人 | 群里 @ 提问，答案带引用；也支持私聊 |
| CLI | CI 集成、脚本化、影响面分析输出到 PR |
| 对外 API | 让别的系统调用（同一套 REST API） |

**连接器是工程量而非难度**：每个 800-1500 行、1-2 周，
含 OAuth、分页、增量游标、限流、删除事件。它扩大覆盖面但不创造新能力，
所以排在最后。

## 八、各客户端特有（阶段 G）

| 客户端 | 特有能力 |
|---|---|
| Web 工作台 | 全部功能的完整界面 |
| 桌面（Tauri） | **全局快捷键唤起搜索**，不用切窗口 |
| 手机（React Native） | 读和问；推送通知 |
| **VS Code 插件** | 选中代码右键提问、内联显示答案、点引用直接跳转 |
| CLI | 脚本化、CI 集成 |
| IM 机器人 | 在用户已经待着的地方回答 |

**IDE 插件是程序员向的最高价值界面**，而且技术上最简单——它就是同一套 API 的客户端。
"这段代码为什么是这样"最自然的提问时机是正在看这段代码的时候。

## 最小可用产品（MVP）是哪些

上面是完整清单，但**先做出来能用的是这一小撮**（阶段 A→B→C→D）：

1. 登录、组织、权限隔离
2. 上传文档，看到处理状态，失败能重试
3. 提问，得到带可点击引用的答案，无依据时拒答
4. 对话历史
5. 部署上线，能被真人用

**这五条做扎实，比十个半成品功能有价值。** 代码感知和智能体治理是在这个地基上加的，
不是并行做的。
