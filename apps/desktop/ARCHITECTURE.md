# 代码与架构工作台

从项目任务页的「代码与架构」进入。页面包含「代码编辑」「架构解析」和「仓库连接」三个标签。编辑能力见[本地代码编辑](EDITOR.md)；架构标签左侧展示分支及本次分析文件，右侧展示 Agent 报告。项目切换保留代码工作区入口，任务和知识入口位于顶部。

## 解析流程

1. 关联已有 Git 仓库，或从授权的 GitHub 仓库克隆。
2. 在左侧预览本次读取的源码片段。Agent 与实际使用的模型显示在解析按钮下方；没有可用模型时先到「AI / API 配置」配置，再到知识工作区选择 Agent 模型。
3. 点击「解析项目架构」，将预览片段发送给该 Agent 当前配置的模型。报告包含技术栈、入口、模块职责、调用和数据流、存储、构建与测试方式，以及无法确认的部分。
4. 点击报告下方的文件引用查看对应片段和行号。解析使用静态源码，不安装依赖、不运行项目命令，也不把静态判断描述成测试已通过。

报告保留在当前页面。切换、解除或更换仓库后清除旧结果；编辑保存刷新源码快照后，隐藏与当前快照不一致的报告。重新进入页面后可再次生成。生成期间源码、分支、仓库关联、Agent 配置或访问权限变化时，拒绝将过时结果作为当前报告返回。

## 读取范围

- 使用 Git 跟踪文件及未被忽略的新增文件，遵守仓库和全局忽略规则；不执行 Git hooks 或 fsmonitor。
- 优先选择 README、架构说明、依赖清单、启动入口及主要源码。最多读取 24 个文件片段，单文件最多 4,000 字符，总片段最多 64,000 字符；文件清单在读取时限制为 2 MB。
- 跳过 `.env`、密钥文件、私钥正文、依赖/构建目录、二进制和超过 128 KB 的文件，不跟随符号链接或目录联接。打开文件后再次核对真实句柄路径，防止读取仓库外的内容。
- 隐藏可识别的密钥赋值、数据库/HTTP URL 中的凭据及常见令牌格式。过滤不是对任意源码秘密的完整识别；可在左侧核对将发送的片段。
- 界面明确标出候选文件数、实际片段数和截断状态。限量采样报告不等于整个仓库的完整审计。

接口与模型返回的文件引用会被校验。审计记录只包含模型、Agent、快照摘要和片段数量，不保存源码内容或模型凭据。

DeepSeek 官方接口默认启用思考模式，会占用输出预算。当前有界 JSON 报告对该官方接口明确关闭思考模式；其他兼容接口不附加该参数。系统提示与解析器使用相同的段落、文本与引用数量限制，采样元数据明确提供截断标记。参见 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。
