# 编程 Agent 与并行工作区

桌面版项目的「代码与架构 → 代码编辑」现在包含编程 Agent 面板。它使用当前项目选中的 Agent、回答模型及本次选择的已启用 Skill。模型配置沿用桌面版的加密配置；不需要在任务中填写 Key。

1. 关联本地 Git 仓库，确保已有一次本地提交。在代码面板选择本次任务的 Agent；不同 Agent 可选择不同模型和 Skills。
2. 描述一个具体修改及验证方式，确认允许向所选模型发送读取的源码、命令输出，并修改本次独立工作区。任务基于提交时的 Git HEAD；原目录未提交的修改和编辑器未保存草稿不会复制进去。
3. 查看实际执行步骤。Agent 可以搜索文件路径、读取源码、修改已有文件或在已有目录中新建文件。
4. 每条命令执行前会显示完整参数数组、工作目录和超时。核对后点击「批准此命令」，或拒绝并停止。
5. 若该命令确实能检验任务要求，勾选「我确认此命令可以验证本次任务的结果」。只有用户确认过的检查实际以 0 退出，且检查后受支持源码没有变化，运行才可标记完成。程序不判断任意命令是否提供充分的测试覆盖；请核对命令、输出和差异。
6. 从运行记录打开本次修改的前后差异；命令期间观察到的变化与文件工具写入分别标记。任务目录、分支、基准提交和 Agent 配置版本均可核对。主编辑器仍显示项目原目录，运行差异显示所选任务的记录。

## 多 Agent 调度与成果审阅

- 不同项目、同项目不同 Agent 可同时运行。每次任务使用独立的 `cairn/agent-<运行编号>` 分支和 `<仓库名>.cairn-worktrees/<运行编号>` 目录；目录位于原仓库旁边，创建失败时会明确停止并保留已创建部分。Git worktree 使用锁防止自动清理，不自动删除分支或文件。
- 顶部「Agent 运行」汇总当前账号有权限访问的项目、任务、Agent、模型、状态、最近进展及结果入口。项目面板可以随时切换运行记录，批准或停止选中的任务。
- 本机默认同时运行 2 个任务，管理员可设置为 1–4 个。本次应用会话内生效，重启恢复默认值。等待命令确认也占用名额；降低上限不会取消已运行任务。一个项目中同一 Agent 的任务串行执行；其余任务按提交顺序选择可运行者，最多保留 40 个运行或排队任务。
- 可选择同项目的一次运行作为前置任务。依赖未结束时不占执行名额；前置失败、取消或中断时，后续任务显示阻塞，不自动重试。前置成功后，提供其摘要和记录的源码差异作为模型参考；代码不自动合并，Agent 必须明确应用需要的改动并重新验证。
- 同项目、同一关联目录的不同任务修改了同名文件时，显示重叠提示及各自结果入口。这表示可能发生合并冲突，并非已经执行 Git 合并或证明无冲突；即使结果相同也需核对。每份成果继续保留，完成状态不代表已经集成。主分支合并、提交、推送和 PR 仍是后续单独操作。

## 执行与数据边界

- 运行期间，原目录仍可手动编辑，草稿保留。存在运行或排队任务的项目不能更换或解除仓库关联；其他项目不受影响。其他编辑器仍可能修改任务目录，文件工具按读取版本检查冲突，失败时保留双方内容。
- 命令以当前系统用户权限执行，可以访问该用户有权限的文件和网络。工作目录、提示词约束和 Git 仓库都不是操作系统沙箱。导入或启用 Skill 不授予命令执行权限。
- 命令参数直接传给进程，不隐式启动 shell。Windows 批处理需要明确使用 `cmd.exe /c` 并确认完整参数。stdin 关闭，不支持交互式终端。命令不继承 Cairn 的模型、数据库或 GitHub 凭据环境变量，但仍享有当前系统用户的文件权限。
- 点击「停止执行」会取消模型请求或终止命令。支持的 Windows 桌面运行时先挂起新进程、加入关闭即终止的 Job Object，再恢复执行；取消、超时和运行时退出都会终止其子进程。POSIX 开发测试只管理同一进程组，不构成 Linux/macOS 桌面支持。
- 每次运行使用提交任务时的 Agent、模型和 Skill 配置快照。切换或修改 Agent 配置影响之后的任务。会话失效、项目权限丢失、仓库关联或任务工作区的分支/HEAD 变化会停止该任务的后续执行；主目录后续提交不改变已捕获的基准。没有自动重试，重启后运行和排队记录标记中断，已经写入的文件不回滚。
- 运行记录以独立 DPAPI 文件保存在数据目录的 `coding-runs/` 下，按账号和项目隔离；包含任务、输出和差异。界面显示全部运行/排队任务及最近 20 次结果，较早记录可经依赖或重叠入口打开；旧记录继续保留在本机。记录和仓库旁边的 worktree 都不进入普通备份，不能把备份恢复当作代码成果或运行记录迁移。旧版单 Agent 记录仍可读取，其改动仍在当时的原目录，不会自动搬迁。

## 当前限制

文件工具使用现有源码筛选规则，排除 Git 忽略文件、凭据文件及不支持的类型；含疑似凭据的文件拒绝发送给模型，不能保证识别任意格式的秘密。命令输出也会发送给模型以继续执行，识别到的常见凭据会被隐藏；请勿批准输出秘密的命令。

新 worktree 只检出 Git 已提交内容，不复制依赖安装目录、忽略文件或未提交修改；所需安装和测试命令仍逐条批准。不自动初始化子模块。配置了 Git clean/smudge/process 内容过滤命令（包括依赖此配置的 Git LFS）的仓库暂不支持；创建工作区前及进入新分支配置后检查并拒绝，避免自动检出触发未经批准的脚本。

单次最多 40 个步骤，上下文最多 256 KiB；单个源码文件最多 32 KiB；工作目录中可记录的源码变更最多 50 个。每条命令最长 120 秒、输出最多 64 KiB。命令差异和测试失效检查以 Git 可见、受支持的源码变更为范围，不将忽略文件、构建产物或仓库外文件纳入差异。外部程序同时修改文件时，命令期间的变化只说明观察时间，不能据此证明修改来源。

模型响应无效、命令失败、测试失败或超过限制时，该任务明确停止并保留记录，其他任务继续调度。完整交互终端、提交、推送与 PR 在后续阶段接入。
