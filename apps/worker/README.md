# apps/worker — 后台摄取 Worker

**从 Day 23 开始建。** 现在是空占位。

职责：把「解析 → 切分 → Embedding → 入库」这条慢链路搬离 HTTP 请求周期。
上传接口只负责校验、存储、创建任务并立刻返回任务 ID。

| Day | 内容 |
|---|---|
| 21 | 任务状态机 `pending/running/succeeded/failed`、对象存储、解析器接口 |
| 22 | PDF/Markdown/TXT 解析、切分、批量 Embedding、pgvector 入库 |
| 23 | Redis 队列、重试、指数退避、幂等键、超时、取消、死信 |

验收里两条最硬的：**API 重启不丢任务**、**同一任务重复执行不产生脏数据**（靠 `external_id`
唯一约束 + 幂等键，不靠"应该不会重复"）。

这块的心智模型和 C++ 线程池 / 任务队列同构，区别是跨进程——失败不是异常传播，
而是状态落库后由另一个进程观察到。
